# 本地声明式插件包（Phase 1A–1F）

本地声明式插件不会运行插件代码、脚本或资源。Manifest v1 仅记录元数据与绑定内容身份的启用偏好；v2 可声明 `host.showInfo` 只读文本命令；v3 另可声明 `host.openPage` 固定页面快捷入口。只有用户明确启用并点击后才执行，不向插件开放网络、业务数据、设置写入或后台执行。v3 需要包含 Phase 1F 的构建，已经发布的 v0.6.1 不支持。首次编写请参阅[插件作者指南](plugin-authoring.md)。

## 发现位置

宿主使用操作系统的用户配置根目录（`dirs::config_dir()`），再追加固定后缀 `EasiFlux Desktop/plugins/local`。这不是应用安装目录，也不是工作目录。

| 平台 | 用户配置根目录约定 | 本地包根目录 |
| --- | --- | --- |
| Windows | 系统 Roaming AppData（通常为 `%APPDATA%`） | `%APPDATA%\EasiFlux Desktop\plugins\local` |
| macOS | `$HOME/Library/Application Support` | `$HOME/Library/Application Support/EasiFlux Desktop/plugins/local` |
| Linux | 绝对路径的 `$XDG_CONFIG_HOME`，否则 `$HOME/.config` | `<用户配置根目录>/EasiFlux Desktop/plugins/local` |

根目录不存在时视为正常的空目录；宿主不会为扫描创建目录。无法安全读取根目录时，本地发现不可用。

## 通过应用导入单文件清单

“已安装插件”和“插件管理”的页头提供 **导入本地清单**；“插件市场”不提供该入口。选择一份普通本地 JSON 文件，在预览中核对名称、ID、版本与作者信息，再点击“确认导入”。原文件不会被修改；导入后的清单默认停用。相同 ID 已存在时拒绝导入，不支持覆盖更新。

文件选择、读取、预览和提交在同一进程内最多同时进行一份。预览令牌只能使用一次，从预览准备完成起 300 秒后失效。预览绑定宿主已经严格解析并规范化捕获的内容；选择完成后，即使原文件被修改、移动或删除，待确认内容也不会改变。到期、取消或目录更新使预览失效时，需要重新选择文件，不能替换预览原先绑定的目录版本。

应用只接受一个普通本地 JSON 文件，不接受目录、ZIP、URI、符号链接、硬链接或设备文件。前端不会把文件路径、原始 JSON、目标槽位、来源或内容指纹提交给安装命令。

## 确认内容与默认停用

确认面板逐项显示名称、ID、版本、描述、发布者和发布者 ID，v2/v3 还列出命令名称与受控动作范围；导航命令显示宿主定义的目标名。发布者信息由清单作者填写，未经认证。本次只复制清单，不运行代码或授予额外权限。导入后默认停用；v1 启用仅记录偏好，v2/v3 启用后提供相应命令。确认不是签名验证、发布者信任或未来清单版本、贡献、权限的授权，也不提供“导入并启用”。

确认成功后，宿主将捕获的规范清单和一份宿主生成的 `ownership-receipt.json` 一起写入自己生成的 `pkg-<32 个小写十六进制字符>` 槽位，再通过完整扫描发布目录。应用不会把导入结果乐观拼接到页面；用户明确启用之前，该内容保持停用。只有包内 receipt、独立管理索引和当前文件对象三方完整匹配时，页面才把包标为 “EasiFlux 管理” 并允许在停用后移除。槽位名、清单内容或其中任何一方单独存在都不授予删除权限。

## 部分失败与重新扫描

导入使用“完整暂存 → 保存当前身份的停用偏好 → 独占提升完整包 → 重新扫描”的顺序，不承诺跨文件全回滚。页面按结果区分以下情况：

| 页面结果 | 含义与后续操作 |
| --- | --- |
| 清单已导入，默认停用 | 完整包已提升，且权威扫描确认了准确的停用内容。 |
| 清单已导入，但保持外部放置 | 完整包已经写入，但管理登记未完成；应用不会删除它。不要再次导入同一插件 ID，应先重新扫描并按页面或人工维护指引确认状态。 |
| 未导入，停用偏好未保存 | 冲突、目录变化、容量或写入准备等在保存停用决定前阻止了导入；按页面提示修正后重新选择。固定空目录或本次安全清理仍可能已经发生。 |
| 导入未完成；该清单的停用偏好已保存，旧启用不会恢复 | 停用决定已安全保存，但包提升没有完成。不要把这一结果理解为无副作用，也不要恢复旧启用。 |
| 清单已写入，但目录结果尚未确认 | 完整包已经越过提交点，但最终扫描无法确认当前显示；点击“重新扫描本地插件”，不要自动重试导入。 |
| 结果尚未确认 | 响应传输、响应校验或内部结果未知；先点击“重新扫描本地插件”确认磁盘状态，不要重放旧令牌或自动重新导入。 |

选择器中的普通取消不会显示错误。重新扫描只读取固定本地包根并采用权威结果，不会启用导入内容，也不会把当前页面切到插件市场。

## 暂存区人工维护

导入与手工包使用同一个固定配置根，目录形状如下：

```text
<用户配置根目录>/EasiFlux Desktop/plugins/
├── managed-ownership.json
├── local/
│   └── pkg-0123456789abcdef0123456789abcdef/
│       ├── manifest.json
│       └── ownership-receipt.json
├── import-staging/
│   └── stage-0123456789abcdef0123456789abcdef/
│       ├── manifest.json
│       └── ownership-receipt.json
└── removal-staging/
    └── remove-fedcba9876543210fedcba9876543210/
        ├── manifest.json
        └── ownership-receipt.json
```

`import-staging` 从不参加插件发现。它最多容纳 16 个直接项，这一计数包含未知、无效或上次中断留下的项；达到上限时，新导入会显示暂存区需要人工检查和清理。旧暂存不会被自动恢复成导入结果，也不会被应用自动删除或递归清扫。

需要维护时，先完全退出所有 EasiFlux 进程，再打开当前平台精确的 `<用户配置根目录>/EasiFlux Desktop/plugins/import-staging`，逐项检查具体的 `stage-…` 目录。新受管候选的完整暂存包含 `manifest.json` 与 `ownership-receipt.json`；中断留下的条目可能不完整，不能因只看到其中一个文件就猜测归属或补写另一个文件。只处理已经逐项确认的条目；如需保留证据，可把该精确条目移到自己选择的备份位置。不要对 `plugins`、用户配置根或 `import-staging` 使用宽泛的递归删除命令。

应用导入没有改变后文的扫描与状态预算：本地根直接项仍为 256、结构合格包仍为 128、单清单仍为 16,384 字节、单次扫描实际读取总量仍为 2,097,152 字节，状态文件仍为 262,144 字节并保留最多 512 个身份。准备新增一个普通包时，当前使用量必须为新增内容保留一个槽位及对应字节预算。

多个 EasiFlux 进程或其他程序同时写同一插件目录／状态文件不受支持。进行导入、启停、移除、维护或手工放置包时，应只保留一个 EasiFlux 插件写入者。

## 受管包与停用后移除

页面按管理状态明确区分三类内容：内置包随应用提供；历史或手工放置的单清单包属于外部包，应用不会删除；新导入且三方证明完整匹配的两文件包才属于 EasiFlux 受管包。历史包不会被自动接管、补写 receipt 或隐藏。

受管包必须先单独停用，页面才显示 **移除本地包**。没有“停用并移除”组合操作。确认面板显示宿主已经解析的名称、ID、版本、发布者和管理状态；移除的是 EasiFlux 管理的副本，不会修改最初选择的源文件。操作无法撤销，但与该内容身份绑定的停用偏好会保留，即使应用进程意外退出也不会恢复为启用。

移除只对当前仍满足 `localDeclarative + managed + disabled + canRemove` 的包开放。内置、外部、启用、已阻止、管理记录冲突、所有权不可用或移除待回退的包都不会被删除。插件运行权限也没有因此扩大：插件请求与实际授予能力仍为空；应用自身已有的内置链接打开能力不属于插件运行权限。

确认后，宿主先保存停用与“正在移除”记录，再把经过验证的受管包独占移动到 `removal-staging/remove-<32 个小写十六进制字符>`。这次移动是移除提交点。页面不会乐观隐藏卡片，只有采纳权威结果快照后才更新目录，也不会自动重放移除命令。

| 页面或汇总状态 | 含义与后续操作 |
| --- | --- |
| 移除准备已回退 | 包仍在本地，但管理记录未完全恢复；当前不可启停或移除。 |
| 已离开发现、清理待完成 | 包已不再参加插件发现，但隔离区仍有经过记录的内容需要维护。 |
| 管理记录冲突 | 现有证据不能安全证明应用拥有该包；应用不会删除它。 |
| 所有权状态不可用 | 受管导入和移除关闭，但外部包仍可浏览；状态允许时仍可启停。 |
| 移除结果尚未确认 | 传输、响应或最终目录发布无法确认；只能重新扫描观察，不能再次自动移除。 |

启动和 **重新扫描本地插件** 只做不删除内容的安全收敛：在证据完整时恢复管理记录，或在源位置和隔离位置都确定不存在时清理过期索引。它们绝不会删除 `removal-staging` 中的隔离内容。

## 移除隔离区人工维护

`removal-staging` 与 `local`、`import-staging` 位于同一个已验证的插件父目录下，最多容纳 16 个直接项。需要人工处理移除待回退、清理待完成或冲突时，必须先完全退出所有 EasiFlux 进程，再逐项检查页面所指状态及精确的 `remove-…` 条目。不要在应用运行期间编辑、移动或删除插件目录内容，也不要对 `plugins`、用户配置根或整个隔离区使用宽泛的递归删除命令。

Linux 与 macOS 的导入和移除只支持单一 EasiFlux 写入者，并要求操作调用期间没有人工目录修改；相邻检查只能尽力发现同一用户造成的名称交换。Windows 的包移动和清理绑定已经打开并验证的对象与父目录句柄，不按之后可能被替换的路径操作；它保证进程崩溃一致性，不承诺突然断电耐久性。所有平台的人工维护都必须遵守“先退出应用”。

自动化破坏性测试只能使用注入的临时配置根和受控测试目录，绝不能指向真实用户配置目录。

## 状态恢复后重新启用

有效的主 `state.json` 会保留本地声明式插件已经明确记录的启用偏好。主文件无效而从合法 `.tmp` 或 `.bak` 次级候选恢复时，宿主只把所有 `localDeclarative` 身份强制恢复为停用；内置插件的决定保持原值，状态 revision 不因这次恢复单独增加。恢复后的本地插件必须由用户逐项明确重新启用。

次级恢复不会在读取过程中写盘；之后的安全重写失败时，规范化后的内存状态和待重写标记会保留并等待重试。未来 schema 或主文件超限仍是终止性错误，不会为了恢复而降级读取旧副本。

## 支持的外部与受管包形状

每个包占据根目录下的一个普通子目录。目录名是无业务含义的槽位：字面前缀 `pkg-` 加 **32 个小写十六进制字符**（`0-9`、`a-f`），即 `^pkg-[0-9a-f]{32}$`。槽位不等于插件 ID、发布者 ID、信任或删除凭据；不要把反向域名 ID 用作目录名。

历史与手工放置包保持原来的单文件外部形状：

```text
<用户配置根目录>/EasiFlux Desktop/plugins/local/
└── pkg-0123456789abcdef0123456789abcdef/
    └── manifest.json
```

新导入的受管候选使用两文件形状：

```text
<用户配置根目录>/EasiFlux Desktop/plugins/local/
└── pkg-0123456789abcdef0123456789abcdef/
    ├── manifest.json
    └── ownership-receipt.json
```

单文件包必须恰好包含区分大小写的 `manifest.json`；两文件包还必须恰好包含区分大小写的 `ownership-receipt.json`。即使在 Windows 上也不能改变大小写。不允许其他文件、隐藏文件或子目录。两个文件都必须是单链接的普通文件；符号链接、硬链接、junction/reparse point 等重定向形状不会授予管理或删除权限。根路径的祖先目录也必须可以安全打开，不能借助链接跳转。

两文件形状本身仍不足以受管：receipt 必须与规范清单和当前槽位匹配，独立管理索引必须与 receipt 和槽位匹配，扫描时重新打开的包目录、清单与 receipt 对象也必须与登记身份匹配。任一证明缺失或不一致时，应用按 external、ownership conflict 或 unavailable 的安全状态处理，不会猜测所有权。

## Manifest v1 示例

将下面内容保存为 UTF-8 JSON 对象。九个字段均必需，键名区分大小写；未知字段、重复字段、缺失字段以及对象之外的表示形式都会被拒绝。此元数据示例的清单版本是 `1`，不是目录传输协议的版本。

```json
{
  "schemaVersion": 1,
  "id": "com.example.notes",
  "publisherId": "com.example",
  "publisher": "Example 作者",
  "name": "本地笔记元数据",
  "description": "仅用于展示本地声明式包的清单信息。",
  "version": "1.0.0",
  "contributions": [],
  "requestedCapabilities": []
}
```

- `id` 和 `publisherId` 使用至少两段的小写 ASCII 反向域名格式，总长至多 128 字节，每段 1–63 字节；段内仅允许 `a-z`、`0-9`、`-`，不能以 `-` 开头或结尾。
- `publisher`、`name` 必须非空白且各至多 80 个 UTF-8 字节；`description` 必须非空白且至多 500 个 UTF-8 字节。中文字节数与字符数不同。
- `version` 必须是有效 SemVer，规范化后的版本文本至多 64 字节。
- v1 的 `contributions` 与 `requestedCapabilities` 必须都是空数组，不声明可执行内容或授权；页面的实际授予权限也为空。
- 发布者名称和 ID 是作者自行填写的元数据，不代表身份认证、签名验证或宿主背书。

## Manifest v2：只读声明式命令

v2 使用相同的九个顶层字段，`schemaVersion` 为 `2`，只允许本地声明式来源；内置目录仍只接受 v1。`requestedCapabilities` 和实际授予权限必须保持为空。完整的两个命令示例见 [workspace-guide/manifest.json](../examples/plugins/workspace-guide/manifest.json)，须手动导入，不会插入生产内置目录。

`contributions` 必须包含 1–16 项，每项严格为下列对象：

```json
{
  "kind": "command",
  "contributionId": "guide.overview",
  "title": "查看使用指南",
  "actionId": "host.showInfo",
  "params": {
    "title": "工作区使用指南",
    "text": "这是插件作者提供的只读说明。"
  }
}
```

- `kind` 与 `actionId` 必须是上例的字符串；不接受其他动作、URL、路径、IPC 名称或能力参数。
- `contributionId` 使用与插件 ID 相同的语法，在同一插件内唯一；不同插件可重用，命令身份始终是插件 ID 加贡献 ID。
- 两个 `title` 均为非空白普通文本，分别最多 80 个 UTF-8 字节；`text` 非空白且最多 2000 个 UTF-8 字节。空白规则包含 Unicode 空白和 U+FEFF；不会把 HTML、Markdown 或 URL 当作可执行内容。
- 所有对象层级拒绝未知、重复、缺失字段和 positional array。全部命令语义参与内容指纹；v1 规范化字节与既有 `v1:sha256:` 指纹封装格式不变（该前缀不是清单版本）。

命令仅在“已安装插件”或“插件管理”的启用卡片中提供，市场不可执行。显示区域标注插件来源与“插件提供的信息，未经认证”，可关闭。开始加载、重扫、启停、导入或移除时撤销按钮/旧信息；停用、离开页面、内容变化、目录不可用或操作结果未知时也撤销。失败或被忽略的启停响应不能恢复执行，须由之后有效的完整目录快照重新确认；重新可用也不会自动恢复旧信息，必须再次点击。目录卡片可能保留用于浏览，但不等于仍获准执行。

### 在命令工作台中查找命令

导入清单并明确启用插件后，打开“已安装插件”，切换到“命令工作台”。工作台集中列出当前确认可用的已启用 v2/v3 命令；“插件列表”仍保留原有插件搜索、状态筛选和卡片命令，两种视图不会互相修改搜索条件。

工作台搜索会忽略首尾空白和大小写，可匹配命令名称、贡献 ID、插件名称或插件 ID。不同插件可以使用相同贡献 ID，列表会同时显示插件名称与 ID 以明确归属；点击带有插件身份的对应动作按钮才会执行当前命令。搜索、启用或恢复可用状态都不会自动选择或执行命令。

只有状态已经确认且命令仍在当前目录中时才会显示可执行条目。开始加载、重新扫描、启停、导入或移除，目录内容发生变化，操作结果未知，切换视图或离开已安装分区时，已经显示的结果都会撤销；恢复后必须再次明确点击。插件提供的标题和正文始终按普通文本展示，不解释 HTML、Markdown 或 URL，也不把 URL 变成可操作链接。

命令工作台不是全局命令面板：它只位于“已安装插件”，不提供全局快捷键、任意目标导航、历史或收藏。“插件市场”只是随应用提供的内置目录，不执行命令，也不是在线市场、下载或安装入口。

## Manifest v3：受控页面快捷命令

v3 保持相同顶层字段、1–16 个贡献、空权限数组和本地来源限制；v1/v2 的接受范围不变。v3 可以混合原有 `host.showInfo` 和以下命令：

```json
{
  "kind": "command",
  "contributionId": "workspace.charts",
  "title": "打开图表工作区",
  "actionId": "host.openPage",
  "params": { "destination": "charts" }
}
```

destination 仅接受 `home`、`trading`、`charts`、`settings.general`、`settings.notifications`、`settings.about`。不接受 URL、路径、账户设置、参数化路由、交易对或订单。预览和执行按钮显示宿主确定的目标名；点击时重新按插件 ID 和贡献 ID 检查当前授权，再由 AppShell 使用现有导航入口打开页面。

打开页面不授权插件读取该页数据、修改设置或提交交易。宿主页面仍可能进行自身正常的数据加载/图表保存；没有数据返回给插件。独立 plugin-smoke 测试宿主没有主应用导航，因此导航按钮不可用，原有只读信息命令不受影响。

导航目标和全部动作参数进入内容指纹，修改后不能继续沿用旧授权。加载、重扫、禁用或结果未知时不能导航；恢复可用不重放旧命令。完整示例见[工作区快捷入口](../examples/plugins/workspace-shortcuts/README.md)。

## 扫描上限与拒绝规则

| 边界 | 精确上限 | 超限结果 |
| --- | --- | --- |
| 根目录直接条目数（包括无效条目） | 256 | 整次本地发现不可用 |
| 结构合格的候选包数（不等于最终有效清单数） | 128 | 整次本地发现不可用 |
| 单份清单读取字节数 | 16 KiB = 16,384 字节 | 拒绝该包，除非同时触发总读取上限 |
| 单次扫描实际读取总字节数 | 2 MiB = 2,097,152 字节 | 整次本地发现不可用 |
| 状态文件（独立于清单与扫描预算） | 256 KiB = 262,144 字节 | 主状态文件读取超限直接使状态子系统不可用、全部启停暂停，不回退旧副本。拟写入状态超限则拒绝该次保存，保留原状态 |
| 保留的状态身份（独立于当前发现包数） | 512 | 第 513 个保留身份的状态修改被拒绝（`plugin_state_capacity_exceeded`），不保存、不改变已有偏好或状态版本 |

实际读取预算包含被拒绝清单的已读字节以及用于检测超限的探测字节。JSON 无效、清单规则不符或包结构不符时，该包不会进入目录；其他有效包仍可被发现，页面只显示拒绝总数，不显示被拒绝内容的名称、路径或底层错误。

包消失后，有界保留的孤立或历史内容身份仍可能占用这 512 个名额；当前目录中包的数量不等于状态身份数量。显式启停当前包会在候选状态中清理同 ID、同来源的旧身份，但不会清除其他包的历史偏好；容量或保存失败时连同该清理一起回滚。

恢复流程检查 `.tmp` 或 `.bak` 时，同样限制每个候选为 256 KiB；超限候选被跳过，没有合法恢复候选时状态子系统保持不可用。

多个有效本地候选清单使用同一 `id` 时，该 ID 的所有本地候选都被拒绝，不按槽位顺序选择胜者。与内置插件 ID 冲突的本地包也被拒绝，内置插件保持不变。目录槽位与 `publisherId` 都不能绕过 ID 冲突规则。

## 重新扫描与启用偏好

本次应用运行首次请求插件目录时会尝试一次发现。之后修改清单不会自动生效；页面切换、普通目录读取和插件状态重试不触发新的本地扫描。准备好包后，在插件页公共页头点击 **重新扫描本地插件**。初次加载或重新扫描期间该按钮不可用，扫描时保留已确认的目录显示。

成功返回的新扫描结果会整体更新本地目录：被移除、无效或发生冲突的包不再出现；整次本地发现不可用时本地目录为空，但不影响内置目录。通信或响应校验失败时，页面保留上次已确认的目录和发现摘要，并显示经过清理的错误提示；修正问题后可再次点击重新扫描。

“已安装插件”和“插件管理”包含内置、本地外部和本地受管内容；“插件市场”只展示内置插件。管理标签分别说明 `内置 · 随应用提供`、`本地声明式包 · 外部放置，应用不会删除` 或 `本地声明式包 · EasiFlux 管理`，并在记录冲突、所有权不可用或移除待回退时显示对应安全限制。v1 本地卡片提示启用仅记录偏好；v2/v3 提供各自受支持的命令，均不运行插件代码。

新内容身份默认停用。宿主偏好绑定插件 ID、来源、发布者 ID 和清单内容指纹，而不是槽位名称。仅调整 JSON 排版或键顺序不改变内容身份；修改清单字段会产生不同内容身份，不能沿用旧内容的启用偏好。移走包不会替作者清除历史偏好，恢复相同内容身份时可以重新匹配该偏好。
