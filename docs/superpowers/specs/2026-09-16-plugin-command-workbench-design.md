# Phase 1E：插件命令工作台

日期：2026-09-16。基线：`main@a5eeabe`（PR #33 已合并）。分支：`plugin/command-workbench`。

## 目标与选择

沿用户已授权的自主开发流程，补齐 Phase 1D 的日常使用入口。现在命令散落在插件卡片中，已安装页只搜索插件元数据；本阶段提供一个集中查找并使用已启用命令的视图。这是本地声明式阶段的增量，不是在线市场或 PRD-14 全局命令面板的交付。

比较三个方向：签名市场需要信任根、撤销、更新和下载的独立设计；插件设置会引入新的持久化及授权语义；命令工作台可以复用已交付的安全门控和只读动作，因此选择命令工作台。详情预览可独立后续扩展，不捆绑进本阶段。

## 范围与交互

- 仅在“已安装插件”提供“插件列表 / 命令工作台”两个原生按钮切换，使用 `aria-pressed` 表达选中状态。默认插件列表；离开该分区、再返回时恢复插件列表。
- 两个视图互斥挂载。管理页保留原有卡片命令；市场不提供命令入口。导入、重新扫描、健康提示继续位于公共页头。
- 工作台只列出当前可执行的本地 v2 已启用命令，按目录顺序及清单内声明顺序展示，不另建注册表，不持久化命令、搜索或结果。
- 每个条目展示命令标题、插件名称、插件 ID、贡献 ID；执行按钮有能区分插件身份的可访问名称。身份必须由 `pluginId + contributionId` 两者共同确定。
- 搜索只作用于工作台，trim 后大小写不敏感，匹配命令标题、贡献 ID、插件名称或插件 ID；不搜索信息正文，不影响原有插件搜索与状态筛选。
- 显示匹配数/可用总数；区分“当前状态尚未确认，暂不可使用命令”“没有已启用的只读命令”和“没有匹配命令”。不暗示搜索或启用会自动执行。
- 用户显式点击后才显示一份只读信息。显示插件归属和“插件提供的信息，未经认证”，使用普通文本并提供关闭按钮。关闭或重新搜索均清空结果。
- 工作台与卡片共用结果渲染组件和结果生命周期组合函数。切换视图、离开页面、开始加载/重扫/启停/导入/移除、内容/目录变更或未知结果时，旧信息同步撤销；恢复可用后必须重新点击，不自动复现旧结果。

## 数据流和接口

`PluginCommandSummary` 仅包含四个字符串：`pluginId`、`pluginName`、`contributionId`、`title`。它不是执行令牌，也不包含结果正文。

Pinia 插件 store 增加派生的 `availableCommands: PluginCommandSummary[]`。提取内部的可执行贡献选择器供派生列表和 `runCommand(pluginId, contributionId)` 共用。保持现有 `commandsAvailable`、`commandContextKey`、epoch、generation、revision 和请求所有权算法原样；投影不可自行建立授权。

`runCommand` 每次点击必须从当前目录重新查找并执行现有安全门控，不接受缓存的贡献对象或正文。`usePluginCommandResult(pluginSource?: () => PluginCatalogItem)` 只拥有临时结果，返回 `result`、`run`、`clear`；所有调用者均同步监听 store 的 `commandContextKey`。工作台不传参数，额外深度监听整个目录；卡片传入 `() => props.plugin`，只额外深度监听自己的插件内容及 props 替换。这样保留同步撤销，不让每张卡片重复遍历整个目录。授权仍只来自 store，不来自观察目标。

这一观察范围优化来自实现期的内存测量：模拟 128 个插件、每个 16 条命令时，重复全目录监听出现秒级开销。它不是原生 UI 测试结论；验收要求保持失效撤销，并避免每张卡片注册全目录深度监听。

`PluginCommandResult.vue` 只负责普通文本展示与 close 事件。`PluginCommandWorkbench.vue` 负责本地搜索、计数、列表和调用组合函数。`PluginMarketplacePage.vue` 只负责两个视图的挂载，不接管业务状态。

## 安全边界与非目标

- 不新增 Rust、IPC、清单版本、权限、依赖、网络请求、下载、签名、脚本执行、路由或全局快捷键。
- 不扩大 v1/v2 的现有接受范围。内置和停用、阻止、锁定、结果未知的插件不能从工作台执行。
- 不新增 localStorage、最近使用、收藏、自动执行或第二份可变插件目录。
- 所有插件文案均为 Vue 普通文本；不解释 HTML、Markdown、URL 或 CSS。
- 不修改交易分支或用户数据；不宣称历史 OS 5 已解决。

## 验收和验证

1. 多个插件可复用 contributionId；列表与点击仍正确归属。停用/v1/阻止项不可执行。
2. 列表与卡片均使用相同安全门控；请求进行中、失败未知、旧快照不能恢复列表或信息。
3. 工作台搜索正确、大小写不敏感，与插件筛选互不干扰；三类空态有区分。
4. 点击显示纯文本且不新增 IPC；重新搜索、关闭、视图/分区切换、重扫和停用撤销信息，恢复后需再次点击。
5. 只做新功能定向 RED/GREEN、一次相关前端回归、类型检查、范围内 lint 与前端构建；不重复整个 Rust/原生 UI 测试。
