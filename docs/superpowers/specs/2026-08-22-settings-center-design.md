# PRD-12 设置中心（Settings Center）设计

日期：2026-08-22

状态：书面规格已由用户复核确认，进入实施计划

## 1. 背景与目标

当前设置入口是一个名为“API 设置”的模态框，只能编辑活动账户凭据、WebSocket 开关和行情轮询间隔。账户管理、资产概览与风险控制则位于独立的一级“账户”导航中。随着插件、通知、全局搜索、快捷键、工作区、国际化和主题等能力陆续建设，现有结构无法承担软件级配置总入口。

PRD-12 将设置中心建设为主窗口内的全页配置入口，并完成以下目标：

- 建立长期稳定、可扩展的设置分类信息架构。
- 将现有账户中心完整迁入“设置 → 账户”。
- 让通用设置独立于凭据编辑器保存，并补齐真实运行时语义。
- 保留缺少凭据时的快速配置弹窗，但不再让它承担全局设置职责。
- 为尚未实现的后续 PRD 提供可点击、无假控件的统一占位页。
- 保持凭据、账户切换/删除和风控配置现有的安全与事务边界。

## 2. 已确认的产品决策

- 设置中心是软件配置总入口，不是扩大后的 API 弹窗。
- 使用方案 A：保留应用一级导航，进入设置后显示独立的设置分类侧栏。
- 设置中心在主窗口内容区全页显示，不创建新的 Tauri 窗口。
- 一级导航移除“账户”，账户管理、资产概览和风险控制全部迁入设置中心。
- 设置齿轮进入设置中心；设置页提供返回入口，一级导航也可直接离开设置。
- 普通设置自动保存；凭据、账户破坏性操作、风控和重连等操作显式确认。
- 不提供覆盖整个设置中心的全局“保存”按钮。
- 普通齿轮入口每次都默认打开“通用”，不记忆上次设置栏目。
- 尚未实现的栏目保持可点击，显示名称、用途说明和“规划中”，不渲染不可用的假控件。
- 行情轮询间隔必须真正影响运行时调度。
- WebSocket 偏好自动保存，但不主动打断当前连接；已连接时提示用户显式重连后应用。

## 3. 范围边界

### 3.1 本阶段包含

- 设置中心页面框架、分类侧栏、栏目切换、返回与深链导航。
- “通用”中的 WebSocket 偏好和行情轮询间隔。
- 通用设置的窄范围后端更新命令、自动保存队列和保存状态。
- 行情轮询间隔对 Rust 行情兜底调度器的动态生效。
- WebSocket 偏好的“保存”和“重连应用”分离语义。
- 现有账户中心迁移：API 管理、资产概览、风险控制。
- “关于”中的应用名称与版本信息。
- 其他已确认分类的统一占位页。
- 将现有 `SettingsDialog` 收窄为缺少凭据时使用的快速配置流程。

### 3.2 本阶段不包含

- PRD-11 插件市场或插件配置的真实能力。
- PRD-13 通知中心、PRD-14 全局搜索、PRD-15 快捷键系统。
- PRD-16 多窗口与布局保存、PRD-17 国际化、PRD-18 主题系统。
- 设置搜索、云同步、配置导入导出、恢复默认值或开发者设置。
- 新的账户、资产或风控业务能力。
- 多窗口设置页、Vue Router 或 React 页面迁移。
- 自动重连当前账户；重连始终由用户明确触发。

## 4. 方案选择

采用“应用导航 + 专用设置分类侧栏 + 分类内容页”的方案。

该方案将设置作为 `AppShell` 的真实页面状态，并在设置内部维护独立栏目。它与现有桌面工作台结构一致，也能容纳后续 PRD，而不会把账户、插件、快捷键等不同复杂度的内容堆进一个长页面。

未采用的方案：

- 搜索优先的单页滚动：初期紧凑，但账户内容较重，后续栏目增多后页面过长且状态边界不清晰。
- 分类卡片首页：发现性较好，但每次修改常用设置都增加一次进入/返回操作。
- 继续扩大模态框：无法承载账户资产、风险控制和未来完整设置体系，也会继续混淆快速配置与软件设置。

## 5. 信息架构

设置侧栏固定为以下分组和栏目：

```text
基础
  通用
  账户

功能
  插件
  通知
  搜索与命令
  快捷键

个性化
  工作区与窗口
  外观
  语言与地区

系统
  关于
```

首版真实页面：

- 通用：WebSocket 偏好、行情轮询间隔和保存/应用状态。
- 账户：API 管理、资产概览、风险控制三个内部页签。
- 关于：应用名称和当前版本。

占位页面：插件、通知、搜索与命令、快捷键、工作区与窗口、外观、语言与地区。

“插件”一级导航仍代表插件市场入口；“设置 → 插件”代表插件启用、权限和插件级配置。两者职责不同，不合并一级插件入口。

产品界面不显示 PRD 编号。占位页只显示栏目名称、简短用途说明和“规划中”状态。

## 6. 导航与页面生命周期

### 6.1 正常进入与离开

- 设置齿轮改为导航到真实的 `settings` 页面，并显示选中状态。
- 通过齿轮进入时，设置栏目始终初始化为 `general`。
- `AppShell` 只在进入设置时记录前一个非设置一级页面，用于“返回工作区”。
- 点击返回按钮回到进入设置前的页面。
- 点击任意一级导航直接离开设置并进入目标页面。
- 从图表页进入或离开设置仍经过现有导航保存链路，确保图表工作区先执行补存。
- 离开设置后销毁设置中心的栏目状态；再次通过齿轮进入不会恢复上次栏目。

### 6.2 显式深链

普通齿轮入口默认“通用”，但应用内部可以使用显式目标进入具体设置：

- 首页“查看资产”进入 `设置 → 账户 → 资产概览`。
- 未来插件、通知等模块也可使用同一结构打开对应设置栏目。

显式深链不构成“栏目记忆”。用户离开后再次点击齿轮，仍回到“通用”。

导航类型采用判别联合，明确区分一级页面、设置栏目和账户内部栏目，避免继续用含义模糊的单一 `section` 字符串：

```text
PrimaryPage = home | trading | charts | plugins | settings
SettingsSection = general | account | plugins | notifications |
                  searchCommands | hotkeys | workspace | appearance |
                  languageRegion | about
AccountSettingsSection = api | assets | risk
```

## 7. 前端组件边界

### 7.1 `App.vue`

- 不再管理普通设置弹窗的显示状态。
- 继续负责启动配置、事件订阅和缺少凭据检测。
- 仅在首次使用或活动账户确实缺少凭据时打开快速配置弹窗。
- 配置读取或自动连接失败继续通过全局错误服务报告，不把所有错误伪装成“需要设置凭据”。

### 7.2 `AppShell`

- 成为一级页面和设置深链的唯一导航所有者。
- 管理活动一级页面、进入设置前页面及当前设置目标。
- 正常齿轮进入时重建默认 `general` 目标。
- 渲染 `SettingsCenterPage`，并移除原一级 `AccountCenterPage` 分支。

### 7.3 `SettingsCenterPage`

- 组合专用设置侧栏和当前栏目内容。
- 不拥有账户、风控或配置持久化业务逻辑。
- 主内容区独立滚动，根布局保持 `min-width: 0`、`min-height: 0` 和 `overflow: hidden`。

### 7.4 `SettingsSidebar`

- 独立渲染已确认的四个分组和十个栏目。
- 使用语义按钮、选中状态及 `aria-current`。
- 首版固定展示，不持久化折叠或宽度状态。
- 使用现有设计令牌和 UI 原语，不复制账户业务状态。

### 7.5 `GeneralSettingsPanel`

- 持有通用设置草稿、最后成功快照和自动保存状态。
- 只编辑 `useWebsocket` 与 `tickerPollInterval`。
- 首次从配置初始化时不得触发保存。
- 不直接拼装或提交完整 `AppConfig`。

### 7.6 `AccountSettingsPage`

- 将现有账户中心迁入设置内容区。
- 内部使用 `API 管理 / 资产概览 / 风险控制` 页签。
- 直接复用 `AccountProfilesPanel`、`AccountAssetsPanel` 和 `RiskControlPanel`。
- 保留资产和风控面板的 `active` 门控，隐藏页签不提前发起私有请求。
- 普通进入账户栏目时默认 API 管理；首页资产深链可直接激活资产概览。

### 7.7 快速配置、占位与关于

- 现有 `SettingsDialog` 收窄并重命名为 `QuickSetupDialog`。
- 快速配置只处理活动账户凭据；成功后按已保存的 WebSocket 偏好连接，不再混合保存通用设置。
- `SettingsPlaceholder` 接收标题与用途说明，统一渲染“规划中”，不放置假开关或禁用表单。
- `AboutSettingsPanel` 从 `appStore.version` 显示应用名称和版本，不在本阶段增加更新检查。

## 8. 通用设置数据流

### 8.1 窄范围命令

新增专用请求和返回模型：

```text
UpdateGeneralSettingsRequest {
  useWebsocket: boolean
  tickerPollInterval: number
}

GeneralSettings {
  useWebsocket: boolean
  tickerPollInterval: number
}
```

`update_general_settings` 必须：

1. 校验轮询间隔是 1 到 3600 的有限秒数；不做毫秒换算。
2. 获取现有账户生命周期/配置写锁。
3. 从最新运行态配置克隆完整 `AppConfig`，只替换两个通用字段。
4. 原子写入配置文件，成功后再更新内存配置。
5. 仅在持久化成功后更新行情兜底调度间隔。
6. 返回后端实际采用的两个字段。

该命令不接收账户、风控、市场上下文、窗口、主题或观察列表字段，因此陈旧的设置草稿无法覆盖其他模块的最新状态。现有 `save_config` 可保留给兼容调用，但新设置中心不得使用它进行自动保存。

### 8.2 自动保存队列

- 普通设置变更使用约 300ms 防抖。
- 同一时间最多一个保存请求在途。
- 保存期间再次修改只更新最新草稿；当前请求结束后合并并保存最新值。
- UI 区分 `idle / saving / saved / error`，不为每次成功弹出 Toast。
- 成功响应只更新最后成功快照，不覆盖请求后产生的新草稿。
- 失败时保留用户草稿和最近成功快照，显示行内错误与重试入口。
- 失败后的权威配置重新读取用于对账，但不得静默覆盖仍为 dirty 的草稿。
- 用户离开页面时，已开始的请求允许完成；尚在防抖阶段的最新草稿立即尝试一次保存。保存失败通过全局错误服务保留可见记录，但不阻止导航。

### 8.3 行情轮询间隔

- 单位明确为秒，输入接受 1 到 3600 的有限数值，保留现有 `f64` 兼容性。
- Rust `MarketFallback` 调度器从配置初始化间隔。
- 设置更新成功后只重建该周期任务，不重启整个调度器，不影响其他任务。
- 旧周期任务在新任务启动前终止，保持单一运行实例。
- 持久化失败时既不更新运行态配置，也不调整调度器。

### 8.4 WebSocket 偏好

- 开关变更自动持久化 `useWebsocket`，但不主动断开当前连接。
- 未连接时不显示重连要求；下一次连接直接使用新偏好。
- 已连接且用户在当前页面改变偏好时，显示“重连后生效”和明确的“立即重连”操作。
- 用户触发重连后复用现有连接服务，并传入已保存偏好。
- 重连失败不回滚已经保存的偏好；配置保存状态与连接错误必须分开展示。
- 用户离开设置而不重连时，当前连接保持原状，下一次自然连接使用新偏好。

## 9. 账户与敏感操作

- API Key 和 Secret 继续只写入系统 Keyring，不进入配置文件或前端可读模型。
- 账户列表继续使用 `present / missing / unavailable` 凭据状态，不用 `has_credentials` 的布尔结果替代三态。
- 编辑现有账户时空 Key/Secret 表示保留；输入任一新值时要求两项同时提供。
- 保存、切换、删除及其回滚继续使用现有账户生命周期串行协调器。
- 删除账户必须显示具体账户并二次确认；活动账户和唯一账户不可删除。
- 风控继续通过独立 `update_risk_config` 显式保存；普通自动保存不得提交任何风控字段。
- 活动账户凭据更新成功后，需要延续旧快速设置流程具备的重连能力，但必须作为账户页中的显式操作和独立错误状态处理。
- 迁移只改变页面归属，不改变资产、持仓、每日盈亏、资金余额或风控账本的业务语义。

## 10. 视觉、滚动与无障碍

- 继续使用 Vue 3、Pinia、Naive UI 和现有 `AppCard`、`AppButton`、`AppIcon`、`AppTabs` 等原语。
- 颜色、间距、圆角、阴影和字号只使用现有语义设计令牌。
- 图标统一使用 `lucide-vue-next`。
- 应用最小窗口为 1024×640；设置侧栏固定约 220–240px，内容区独立滚动且不得产生页面级横向滚动。
- 默认保持当前深色主题；本 PRD 不实现主题切换。
- 不使用毛玻璃、复杂渐变、过度阴影或与现有产品不一致的动效。
- 设置分类、页签、返回和操作按钮必须可键盘访问，并提供可读标签、焦点环和选中语义。
- 保存失败使用 `role="alert"`；保存中/已保存状态使用非打断式状态文本。
- 占位页没有可聚焦的假控件。

## 11. 错误处理与恢复

- 配置尚未加载：通用表单显示加载态并禁止编辑，不使用默认草稿覆盖未知配置。
- 普通设置校验失败：在字段附近显示错误，不发起 IPC。
- 配置持久化失败：保留草稿、显示错误、允许重试；后端运行态和调度器保持原值。
- 快速连续修改：单飞队列保证最后草稿获胜，旧响应不得覆盖新输入。
- 调度器重配：设计为持久化后的本地无失败状态切换；若实现中发现可失败步骤，必须返回错误并保持旧周期任务，不得报告已应用。
- WebSocket 重连失败：偏好仍为已保存，连接错误单独显示，当前连接状态以连接 store 为准。
- 账户或 Keyring 错误：继续使用现有脱敏错误、恢复态和操作禁用逻辑。
- 资产某一分区失败：不清空其他成功分区。
- 风控账本不可用：继续使用现有 fail-closed 语义，设置中心迁移不得降级。

## 12. 测试设计

### 12.1 前端

新增设置中心集成测试并扩展现有导航测试：

- 点击齿轮进入真实设置页面、齿轮高亮且默认打开“通用”。
- 切换栏目、离开后再次点击齿轮，仍回到“通用”。
- 返回按钮回到进入设置前页面；点击一级导航直接退出设置。
- 一级导航不再出现账户按钮。
- 首页“查看资产”深链到设置账户的资产页签。
- 账户三个现有面板正确切换，隐藏资产/风控页签不提前请求数据。
- 所有规划栏目可点击并显示统一占位，不存在假控件。
- “关于”显示应用名称和版本。
- 通用设置首次渲染不保存；变更防抖、单飞、合并且最后草稿获胜。
- 保存成功、失败、重试和失败后对账均保持正确草稿与状态。
- 轮询间隔前端校验使用秒且限制为 1–3600 的有限数值。
- WebSocket 变更保存后不自动重连；用户操作后才调用连接服务。
- 配置保存失败不触发连接副作用；重连失败不伪装成保存失败。
- 缺少凭据时快速配置仍可用；正常点击设置不会打开弹窗。
- 快速配置和账户页不回显密钥，现有凭据失败与并发测试继续通过。

### 12.2 Rust

- 通用设置命令只修改允许字段，其他 `AppConfig` 字段保持不变。
- 轮询间隔拒绝非有限值、0、负数和大于 3600 的值。
- 配置写入失败不更新内存配置或调度器。
- 通用设置与市场、窗口、风控和账户更新并发时不丢失任一模块字段。
- 调度器从持久化配置初始化行情兜底周期。
- 动态更新只替换 `MarketFallback` 周期任务，并确保不存在重复任务。
- 更新周期时正在运行的任务遵守现有单飞协调，不产生并行重复请求。
- 现有配置主文件、临时文件、备份恢复和风险严格校验测试继续通过。

## 13. 验收标准

- 设置中心成为主窗口内真实全页，不再以 API 设置弹窗代表软件设置。
- 设置侧栏完整展示十个已确认栏目及四个分组。
