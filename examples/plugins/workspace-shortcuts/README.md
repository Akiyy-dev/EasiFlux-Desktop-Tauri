# 工作区快捷入口：Manifest v3 示例

需要包含 **Phase 1F** 的 EasiFlux 构建。已经发布的 **v0.6.1 不支持 v3**，会拒绝这份清单；在旧版本体验只读命令，请使用 [workspace-guide](../workspace-guide/README.md)。

本示例不是自动安装的内置插件，不需要填写任何 API Key、Secret、账户 ID 或服务地址。

## 使用

1. 打开「插件 → 已安装插件」，点击「导入本地清单」，选择本目录的 `manifest.json`。
2. 核对名称、作者和宿主显示的动作/目标，再确认导入。作者元数据未经认证；导入后默认停用。
3. 明确启用后，可在插件卡片或「命令工作台」点击「打开页面：图表工作区」「打开页面：交易页」「打开页面：通知设置」。每次点击只打开一个已有页面。
4. 点击「查看快捷入口说明」对应的显示信息命令，查看纯文本说明。搜索或启用本身不会执行任何命令。
5. 回到插件页，先停用再移除 EasiFlux 管理的副本；本目录的原始示例不会被删除。

打开交易页不等于下单，打开设置页不等于修改设置。目标页面可能按宿主现有流程加载行情或账户信息，但不会将任何数据返回给插件。

## 体验更新前比较（Phase 1G-1）

需要包含 **Phase 1G-1** 的构建；只有 Phase 1F 或已发布 v0.6.1 的构建不提供此比较界面。

1. 先正常导入 `manifest.json`（1.0.0）；无需启用即可比较。若曾移除示例，先重新导入它。
2. 再点击“导入本地清单”，选择 [update-candidate.json](update-candidate.json)（相同 ID，1.1.0）。
3. 在“同 ID 清单比较”中核对：版本与描述变化；新增 `workspace.general`；移除 `workspace.trading`；`workspace.charts` 的标题和目标从图表变成首页；通知入口移到前面。
4. 本示例故意保留 `workspace.charts` ID 来演示：命令 ID 相同不意味着行为未变，必须查看宿主显示的真实目标。
5. 此时只能查看或关闭，不能覆盖导入。关闭会取消本次预览，原来的 1.0.0 和启用状态不会被比较替换。此阶段没有版本回滚按钮。

如果目录中没有 1.0.0，同一候选文件会作为普通新 ID 导入预览；因此要按以上顺序体验比较。“目录中未发现”也不是磁盘无冲突的承诺，正式导入仍会重新检查。

## 边界

- 不执行脚本、任意 IPC、外部链接、路径或后台任务，不申请权限。
- 只有六种固定导航目标，见[作者指南](../../../docs/plugin-authoring.md)；不能传账户、交易对、订单或任意设置参数。
- 加载、重扫、操作结果未知和停用时不能执行。恢复可用后需要重新点击，不重放旧命令。
- 独立 plugin-smoke 测试宿主没有主应用导航，导航按钮不可用；这不是清单损坏。
- 同 ID 覆盖更新尚未支持。不要直接编辑受管副本或所有权记录；如必须人工更换，先保留原始清单，再停用、正常移除旧副本并导入新清单。这是两个独立操作，不是原子更新，也没有失败自动恢复。
